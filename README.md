# Habit Tracker

**Habit Tracker** — backend-часть SPA-приложения для создания полезных и приятных привычек по принципам книги Джеймса Клира «Атомные привычки».

Пользователи могут управлять собственными привычками, просматривать публичные привычки других пользователей и получать напоминания в Telegram по заданному расписанию.

* **СУБД:** PostgreSQL
* **Брокер сообщений:** Redis
* **Фоновые задачи:** Celery, Celery Beat
* **Telegram:** Telegram Bot API
* **Документация API:** drf-spectacular, Swagger UI, ReDoc
* **Менеджер зависимостей:** Poetry
* **Контроль версий:** Git / GitHub

# Структура проекта

Проект состоит из трёх приложений:

* **habits** — модель привычки, валидация, пагинация и API для работы с привычками;
* **users** — пользовательская модель, регистрация и JWT-аутентификация;
* **telegram_bot** — отправка уведомлений через Telegram Bot API и Celery-задачи.

Общие настройки, маршруты и конфигурация Celery находятся в каталоге `config`.

# Функциональность

## Привычки

Привычка содержит:

* владельца;
* место выполнения;
* время выполнения;
* действие;
* признак приятной привычки;
* связанную приятную привычку;
* периодичность выполнения в днях;
* вознаграждение;
* продолжительность выполнения;
* признак публичности;
* время последнего отправленного напоминания.

Полезная привычка может иметь одно вознаграждение: текстовое описание либо связанную приятную привычку.

Приятная привычка используется как награда за полезную и не может иметь собственного вознаграждения или связанной привычки.

## Валидация

Для привычек проверяется:

* вознаграждение и связанная привычка не указываются одновременно;
* время выполнения не превышает 120 секунд;
* связанной может быть только приятная привычка текущего пользователя;
* приятная привычка не содержит вознаграждение или связанную привычку;
* периодичность выполнения составляет от 1 до 7 дней.

## Пагинация

Списки привычек используют `LimitOffsetPagination`. По умолчанию API возвращает 5 привычек на страницу вместе с полями `count`, `next`, `previous` и `results`.

Количество и смещение можно передать через параметры `limit` и `offset`.

# Пользователи и аутентификация

Используется собственная модель пользователя на основе `AbstractUser`. Вход выполняется по email, поле `username` отключено.

Реализовано:

* регистрация пользователя;
* получение JWT-токенов `access` и `refresh`;
* обновление `access`-токена;
* хранение идентификатора Telegram-чата пользователя.

Для доступа к защищённым эндпоинтам передайте токен в заголовке:

```
Authorization: Bearer <access-токен>
```

---

# Права доступа

Авторизованный пользователь может:

* создавать привычки;
* просматривать только собственные привычки;
* редактировать собственные привычки;
* удалять собственные привычки;
* связывать полезную привычку только со своей приятной привычкой.

Список публичных привычек доступен без авторизации. Публичные привычки других пользователей нельзя редактировать или удалять.

# Telegram-уведомления

Celery Beat каждую минуту запускает задачу поиска привычек, назначенных на текущие часы и минуты.

Уведомление отправляется, если:

* у владельца указан `telegram_chat_id`;
* время привычки совпадает с текущим временем;
* с предыдущего уведомления прошло количество дней, указанное в поле периодичности.

Сообщение содержит действие, место, время, продолжительность выполнения и выбранное вознаграждение. После успешной отправки в привычке сохраняется время последнего уведомления.

Пользователь самостоятельно узнаёт идентификатор своего Telegram-чата и указывает его при регистрации.

# Переменные окружения

Создайте файл `.env` на основе `.env_example`:

```
cp .env_example .env
```

В `.env` указываются:

* `DJANGO_SECRET_KEY` — секретный ключ Django;
* `DEBUG` — режим отладки;
* `ALLOWED_HOSTS` — разрешённые домены Django;
* `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT` — параметры PostgreSQL;
* `CORS_ALLOWED_ORIGINS` — разрешённые адреса фронтенда;
* `CELERY_BROKER_URL` — адрес Redis для очереди задач;
* `CELERY_RESULT_BACKEND` — адрес Redis для результатов задач;
* `TELEGRAM_BOT_TOKEN` — токен Telegram-бота.

Файл `.env` содержит секретные данные и не должен добавляться в Git.

# Установка и запуск

Для проекта требуются Python 3.14, Poetry, PostgreSQL и Redis.

1. Установите зависимости:

```
poetry install
```

2. Создайте `.env` на основе `.env_example`, заполните переменные и создайте базу данных PostgreSQL.

3. Примените миграции:

```
poetry run python manage.py migrate
```

4. Запустите Redis:

```
brew services start redis
```

5. В отдельных терминалах запустите Django, Celery Worker и Celery Beat:

```
poetry run python manage.py runserver
poetry run celery -A config worker --loglevel=info --pool=solo
poetry run celery -A config beat --loglevel=info
```

# Основные эндпоинты

## Пользователи

* `POST /api/users/register/` — регистрация;
* `POST /api/users/token/` — получение JWT-токенов;
* `POST /api/users/token/refresh/` — обновление `access`-токена.

## Привычки

* `GET /api/habits/` — список привычек текущего пользователя;
* `POST /api/habits/` — создание привычки;
* `GET /api/habits/{id}/` — просмотр собственной привычки;
* `PUT /api/habits/{id}/` — полное редактирование собственной привычки;
* `PATCH /api/habits/{id}/` — частичное редактирование собственной привычки;
* `DELETE /api/habits/{id}/` — удаление собственной привычки;
* `GET /api/habits/public/` — список публичных привычек.

# Тестирование

В проекте реализовано 26 тестов с помощью `unittest`, `TestCase` и `APITestCase`.

Проверяются:

* регистрация, создание пользователей и JWT-аутентификация;
* CRUD привычек, права владельца и публичный список;
* пагинация и валидаторы привычек;
* отправка сообщений через Telegram API;
* периодичность Celery-уведомлений и сохранение времени отправки.

Внешние запросы к Telegram заменяются с помощью `Mock` и `patch`, поэтому во время тестирования реальные сообщения не отправляются.

```
poetry run python manage.py test
```
